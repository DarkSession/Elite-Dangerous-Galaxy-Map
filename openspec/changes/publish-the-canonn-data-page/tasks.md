## The implementation review gate

The `openspec-implementation-reviewer` subagent ran twice, on the change id, with a second
reviewer for the second pass.

**First pass: BLOCK**, on three findings, all confirmed by the main session before any fix.

1. 36,137 records repeated one of their own keys as their description, against a SHALL.
   Fixed by a guard on both exits of `convertSource`, not in the clouds reader, because the
   `literal` reader does not call `reading()`. The data was rebuilt.
2. The guard against a shrinking tree was dead on the path it was written for: the `continue`
   returned before `checkAgainstHeld`. A cold cache on a day the bucket answered 5xx would
   have deleted the committed sets and exited 0. Fixed, and a test now drives `main`.
3. No entry carried a `description`, so every entry opened with a blank detail panel. Fixed
   by `describeEntry()`, and asserted in three places.

**Second pass: APPROVE WITH NOTES**, with the three blocks confirmed fixed on the code.

Acted on: the fifth source shape added to the spec list, the source arithmetic replaced with
the delivered 101 distinct sources, the latent double fetch closed, the split held to its keys
by two tests over the committed tree, two wrong comments corrected, and one fixture test added
for the source-tree shape.

Recorded and not fixed:

- **Nineteen of the 29 readers have no fixture test**, and eleven of the twelve readers on the
  source-tree shape are among them. The evidence for those readers is the live run alone.
- **`fetchSource` writes its cache without a temporary file**, so an interrupted write leaves a
  short file the next run reads as complete. A truncated JSON fails the build loudly; a codex
  CSV short by under 10 percent commits a short set. The 10 percent guard is the answer to it.
- **`fetchSource` never invalidates the cache** and there is no refresh flag. Task 3.3 reads
  the conversion and not the download. The refresh is `rm -rf apps/demo/data/canonn/`.
- **The dialog grouping is read through the handle**, not by opening the dataset dialog.
- **`assetsInlineLimit: 0` is global to the demo build**, which the spec permits in as many
  words, so the other pages stop inlining small assets too.
- **A map that drops because its address fails today prints `converts to no record`**, because
  the vocabulary word comes from the table row. The word is in the vocabulary, so no rule
  breaks, and the per-source line prints the address and the status.

One finding was declined. The reviewer read two counts in `THIRD_PARTY_NOTICES.md` as off by
one. The main session first declined it on a count of its own, and that was wrong: the
difference is `dumpr/hyperdictions.json`, which sits under `dumpr/` and is a JSON dump and not
a four-column codex CSV. The counts are 18 and 157, the notices now say so, and the spec states
the boundary.
